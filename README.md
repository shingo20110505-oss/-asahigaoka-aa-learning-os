# RISE — 総合学習ワークスペース

旭丘高校を目指す学習をまとめる、静的PWAとPCチャットです。ロゴは既存のv5を維持しています。

- 英語長文130本：段落メモ、要約、対訳、語彙、読解ガイド、読み直し日程。
- 復習114項目と過去の履歴の移行・バックアップ。
- 歴史年表：既存1,000件のIDを保持し、出典付き追加・比較・因果関係・メモ。
- 国語語彙、公式入試資料、10種類の数学・理科モデル、学習ノート、教材・予定・集中記録。
- 管理者・ゲスト別のPCチャット。ゲスト履歴はブラウザごとに分離し、引き継ぎコードで移動できます。

## PCで使う

Node.js 24以上で `RISE-PC.cmd` を開きます。学習画面は http://127.0.0.1:4318 、PC設定は http://127.0.0.1:4320 です。

管理者はPC設定からChatGPTでCodexにログインします。ゲストも同じChatGPT契約のCodexを使え、モデル・推論の強さを役割別に指定できます。管理者 `gpt-6-astra` / `high`、ゲスト `gpt-6.1-sol` / 標準設定に対応します。Codexの各リクエストは独立した一時会話で実行し、その利用者の会話だけを入力します。ゲストの履歴・添付・引き継ぎコードの分離は維持します。既存のOllama設定も選択できます。有料OpenAI API、PHPは使用しません。パスワードは8文字以上・管理者とゲストで別に設定し、PC内にsalt付きscryptで保存します。公開コードには保存しません。

MP4は元ファイルの保存・再生・時刻付き静止画の抽出に対応します。AIには静止画を送ります。動画全体や動画音声の解析ではありません。保存量にアプリ独自のGB上限はありませんが、PCの空き容量とAI入力上限は別です。

## 別端末から使う

`relay/` はCloudflare WorkersとSQLite型Durable Objectを使うHTTPS中継です。PCは外向きの接続だけを行います。PC設定画面やCodex RPCは公開しません。中継は会話・添付を永続保存せず、会話とファイルはPCの `.rise-private/` に保存します。PCが停止するとAIチャットはオフラインになります。

GitHubの `RISE authenticated PC relay` ワークフローは、既存のCloudflareデプロイ資格情報と、追加の `RISE_RELAY_TOKEN` シークレットを使用します。同じ接続キーをPCの非公開設定に置き、PC設定のHTTPS URLを公開先に合わせます。キーはブラウザ・URL・公開成果物には含めません。

チャットも元のGitHub Pagesの `#/chat` で開きます。画面を別ドメインへ移動せず、AIworknaviの固定ゲートウェイへ有限のPOSTで通信し、回答を定期取得します。Pagesのチャット通信はService Workerの許可に依存しません。第三者Cookieには依存せず、期限付きログイン情報をブラウザの専用IndexedDBに保存します。パスワードやPCの中継キーは保存しません。ログアウトするとログイン情報を削除し、ゲストの端末識別情報だけを残します。

チャット右上の「最大化」で会話と入力欄を広げ、「元の表示」またはEscで戻れます。下書きや添付は表示切替で消えません。

年表のカードをタップすると詳細を開き、年代・出来事の部分はそれぞれタップで隠す／表示できます。S・A・Bは元の教材のランクです。詳細で自分用のランクを保存でき、元の1,000件のデータは変更しません。

初回オンライン時に画面と全教材をService Workerへ保存します。「設定とデータ」の「オフライン準備済み」を確認すると、未閲覧の英文・語彙・年表もネットワークなしで開けます。ノート・学習記録・自分で保存した資料は既存のIndexedDBを使います。AIの新しい返答・外部リンク・オンライン音声は対象外です。チャットAPIやPCの非公開ファイルは教材キャッシュに入りません。保存を制限するブラウザでは準備できない場合があり、ブラウザデータを削除した場合は再保存が必要です。

チャットにオンラインでログインすると、会話本文を専用のIndexedDBへ順次保存します。「オフライン用の本文：N / N件 保存済み」が目安です。画像・MP4・ファイルは表示・ダウンロードまたは「オフライン用に保存」で読み込んだものを保存します。通信が切れたりPCに接続できなくなったりしたときは、保存済みの会話を閲覧専用で開けます。再接続時に入力を自動送信することはありません。

オフライン履歴はサーバーが確認した利用者の不透明ID、役割、ログインセッションに結び付き、管理者・各ゲストを分離します。ログイン期限を過ぎたコピーは開けません。ログアウト・利用者変更では端末の本文・添付コピーを消し、PCの原本は保持します。別タブにもログイン状態変更を通知し、古いリクエストによる再保存を拒否します。APIトークン・パスワード・CSRFは履歴コピーに含まず、通常の学習データのバックアップにも混ぜません。

管理者のチャット履歴は同じPCの履歴を開きます。以前の別ドメインで使っていたゲスト履歴は、そちらで発行した引き継ぎコードを元のRISEのログイン画面に入力すると移せます。学習ノート・復習記録は元のRISEの保存先をそのまま使います。

## 手書き消去と端末内AIの検証

AI学習ツールまたはチャットの「＋ ツール」から `#/handwriting-clean` を開きます。赤・青の候補抽出、「消す／残す」ブラシ、複数枚の逐次処理、全画面プレビューに対応します。結果は原本と別に資料室へ保存します。キャッシュ準備後は通信なしでも処理・保存できます。黒い筆記の自動判定や、印刷に隠れた文字の復元は保証しません。比較と実測は [手書き消去の評価](docs/handwriting-evaluation.md) を参照してください。

`#/device-ai` は端末内LLMの検証画面です。今回のWebLLM・Windows/AMDでの比較では、日本語学習チャットへ自動採用するモデルはありません。比較機能とオフライン会話の仕組みは実装していますが、通常チャットへの自動切り替えは無効です。PCでの計測や画面サイズ変更をA16 iPad実測とは扱いません。モデルは利用者が比較を開始したときだけダウンロードします。詳細は [端末内AIの評価](docs/local-ai-evaluation.md) を参照してください。

## 検証と公開

`node --test tests/rise-*.test.mjs` と `node scripts/build-rise.mjs`、`node scripts/validate-rise-build.mjs` を実行します。公開するのは `dist/` の許可された静的ファイルだけです。Worker開発用依存は `pnpm install --frozen-lockfile` で固定します。

設計・検証状況は [docs/RISE_REBUILD.md](docs/RISE_REBUILD.md)、入試調査は [docs/ASAHIGAOKA_RESEARCH.md](docs/ASAHIGAOKA_RESEARCH.md) を参照してください。学校の実機・ネットワークでの到達性は別途確認が必要です。
