# 教材検索とローカルLLMの比較

## 状態

測定ページのみ公開する。通常のRISEでローカルモデルを有効にする変更はない。iPad A16の実機測定と採点が終わるまで採用しない。

## 固定した条件

- `experiments/rag/questions.mjs` の24問。地理8・歴史4・古文4・漢文3・英語4・資料不足1。採点基準は推論前に固定し、モデルと検索へ渡さない。
- 同じモデル・同じ質問を、検索なし、検索原文、検索＋LLMで比較する。検索原文とRAGは同一の3件・最大1,800文字を使う。
- 検索は質問そのものと句点などで分けた追加クエリ。最大4クエリは入力サイズの上限であり、通常Codexの検索を1回に制限する仕組みではない。正解から検索語を作らない。
- temperature 0.2、seed 42、出力最大512 tokens、context 4096。質問ごとに会話を独立させ、KV再利用なし。生成方式の順は問題ごとに反転。
- Qwen3 4B Instruct 2507のQ3_K_M（2,075,618,400 bytes）とQ4_K_M（2,497,281,120 bytes）。Unsloth変換、リビジョン固定。wllama 3.8.1、Safari互換ランタイムも同一バージョンを同梱。
- 初回ダウンロード・モデルロード・教材読込/索引作成・質問ごとの検索・生成開始・完了を別に記録。初回文字の時間はWorkerで最初の空白以外の文字を取得した時点であり、画面のペイント完了ではない。推論欄はウォームアップ後。RAGの質問時間には検索を加算する。
- 端末ラベルは利用者の申告。User-AgentをiPadに変えただけで実機と認定しない。GPU/nativeを含む総RAMはブラウザから正確に測れない。ページ中断の原因をOOMと決めつけない。

## 採点と採用

完全正答=必要な事実と理由が揃い、誤りなし。部分正答=正しいが必要な説明が不足。誤答=誤った事実・因果、資料不足の断定。原文方式も「答えが十分に含まれるか」で採点し、利用者が追加で計算しなければならない場合は完全正答にしない。キーワード一致率を正確さと呼ばない。

目安は完全正答21/24以上、重大な誤断定0。A16実機で回答開始中央値5秒/95%点10秒以内、完了中央値20秒/95%点45秒以内、保存済みロード60秒以内。2回の安定動作と、通信を切った全ページ再読込を必要とする。未達・未測定は採用しない。これはこの比較で置いた目安であり、iPadで達成済みという意味ではない。

## 測定方法

`npm run build` → `node scripts/benchmark-rag.mjs search` / `qwen3-4b-q3` / `qwen3-4b-q4`。生回答は `test-results/rag/` に保存。PCスクリプトは専用Chromeプロファイルだけを使用する。オフライン確認はブラウザをofflineにし、HTTPサーバーを止めて全ページ再読込、未キャッシュURLの失敗と保存済みモデルの回答を確認する。

iPadでは `/labs/rag/` を開き、端末を選択し「3方式を測定」。終了後に結果JSONを保存し、チャットへ添付する。通信を切って再読込後の測定も保存する。測定画面は本体のオフライン一括取得から除外され、モデルはボタンを押した時だけ取得する。会話・ノート・パスワード・個人ファイルは参照も送信もしない。
