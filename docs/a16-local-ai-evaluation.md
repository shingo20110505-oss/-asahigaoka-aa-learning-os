# RISE：iPad A16向けローカルAIの追加評価

評価日：2026-10-26 JST。**今回の5候補は本番採用しない。** 3B〜4Bへの大型化と別ランタイムで比較したが、学校学習で見逃せない誤答が残った。A16実機での性能・安定性も未確認のため、mainへの統合・公開は行っていない。既存のオンラインAI、役割別の履歴、学習データ、ロゴ、公開URLは変更していない。

独立クローンの `research/ipad-a16-local-llm` ブランチで、静的な比較ラボ・回答原文・測定記録を残した。基点は `0f5aaa80f304a0476ae34c287e092f35839a6835`。本番チェックアウト、稼働プロセス、`.rise-private` は操作していない。

## 結果

以下は **Windows PC（Ryzen 5 7535U / Radeon RDNA2 / RAM約16GB / HeadlessChrome 156）での実推論**。画面幅をiPad相当にした表示確認は別に実施したが、A16性能の代替測定ではない。

|---|---:|---:|---:|---:|---:|---:|
|Qwen2.5 3B / WebLLM 4bit|1.75GB|1|7|2.87秒|12.11 tok/s|10.85秒|

GBは10進表記。容量は固定配布物の合計であり、通信量やRAM使用量ではない。WebLLMのリストには実行時に使用しないtokenizer補助ファイルも含む。初字はウォームアップ後の各独立質問で最初の表示内容が出るまで、decodeはruntimeが報告した生成区間の速度、終了までの時間はprefillを含む。中央値は10個を昇順に並べた中央2値の平均。

採点は0＝誤り・根拠のない主張・核心欠落、1＝一部正しいが修正が必要、2＝必要な説明を含め正しく使える、の意味評価。原文をCodexが確認したもので、独立した人間の採点ではない。各問1回、計10問の小規模試験であり、一般的な正答率やモデル全体の優劣を確定するものではない。[全採点と理由](a16-evidence/answer-review.json)、[集計と測定値](a16-evidence/summary.json)

特に採用を止めた回答は以下。

- Qwen2.5 / WebLLM：「顕著」を「けん attached」とし、√9＝±3に同意。正しい英文を出しても説明では「yesterday」を「去る」という助動詞のように扱った。
- Qwen3 / WebLLM：1/2＋1/3を11/6とし、5/6を繰り返し否定。「顕著」は「けんちゅう」と誤読。
- Qwen3.5 / WebLLM：「顕著」を「けんきゅう」と誤読。画像を渡していないのに、提示画像には数値がないと述べた。会話では一次関数をx＋yが一定と説明。
- Qwen2.5 / wllama：√9＝±3を肯定。分数の答えは5/6でも、通分の操作を「それぞれを6で割って」と誤説明。
- Qwen3 2507 / wllama：分数・平方根は改善したが、「顕著」を「かんじょう」と断定し「けん」を否定。鎌倉時代を1185〜1573年とし、tiredを「お腹が空いていた」と訳した。

2507版は今回の採点では最も高かった。ただし原モデル・量子化・runtimeを同時に変えており、改善をwllamaだけの効果とみなせない。3bit版が4bit版より優れるという結論でもない。Q4_K_Mの単一ファイルは2GiBを超えるため、今回のwllama経路では2GiB未満のQ3_K_Mを選んだ。大型モデルへの一律の容量制限は設けていない。

誤りの原因が原モデルの重み・量子化・runtime・GPUドライバーのどこにあるかは切り分け未完了。CPUのみの参照推論や別GPUでの対照試験は行っていない。今回の実行条件で採用を見送る判断であり、別OSや別の変換配布物でも同じ結果になるとは限らない。

## 起動・オフライン・メモリ

5候補すべてで、取得後にHTTPサーバーを停止し、ネットワークを無効化してページ全体を再読み込みした後、保存済みモデルが回答した。各候補の `*-offline-proof.json` にサーバー停止と未保存URLの取得失敗を記録している。これは上記Windows環境での成功であり、Safariのキャッシュ保持を保証しない。

|モデル・経路|初回のロード|オフライン再ロード|意図的なWorker終了後の再ロード|
|---|---:|---:|---:|
|Qwen2.5 / WebLLM|58.02秒※|3.96秒|4.41秒|
|Qwen3 / WebLLM|66.03秒|7.55秒|8.63秒|
|Qwen3.5 / WebLLM|76.61秒|8.13秒|10.21秒|
|Qwen2.5 / wllama|68.06秒|5.05秒|5.78秒|
|Qwen3 2507 / wllama|74.85秒|6.12秒|10.97秒|

※Qwen2.5の58.02秒は後述の除外した予備試行から、取得・保存・ロードの記録だけを引用。採点対象の再試行は保存済みで7.53秒だった。初回ロードはモデル取得・保存・コンパイル等を含むが、その後の最初の生成時にも準備時間がかかる。例えばQwen3.5の最初の1＋1は初字23.71秒で、通常質問の中央値3.97秒とは異なる。

Windowsの独立Chromeに属するプロセスだけを10秒間隔で計測した。private commit最大値 / Working Set合計最大値は、Qwen2.5 WebLLMが3.54 / 3.99GB、Qwen3.5が5.54 / 6.25GB、Qwen2.5 wllamaが3.61 / 5.35GB、2507版が4.83 / 7.03GB。Qwen3 WebLLMはこの計測を導入する前の試行のため欠測。**private commitは物理RAMではなく、Working Set合計は共有ページを重複計上し得る。GPUドライバーの全常駐量も含まれない。** 10秒間隔の標本最大であって真の瞬間ピークではない。A16の必要RAM量には換算できない。

保存領域は5候補を順次取得した同一の検証origin全体で約10.62GBになった。モデルごとの実行RAMとは無関係。wllamaのログでは2507版のGPUモデルバッファ約1974MiBに加えKV約576MiBなどがあり、ファイルサイズだけで実行メモリは決まらない。ログに現れる「2048MiB free」も端末の実空きRAM測定値として使わない。

## 会話・長い履歴・削除

実際にモデルが応答した4往復では、最後に合言葉と2つの計算結果を再掲させた。Qwen2.5 WebLLMは値の対応を混同。残る4候補は合言葉と数値を再掲したが、途中の説明まで常に正しいわけではない。最終ターンの初字は順に17.38 / 27.14 / 56.65 / 21.46 / 39.87秒だった。履歴を全て入力し直す条件である。

続いて21往復分の固定履歴を入力し、冒頭の合言葉とy＝−5を取り出せるか検査した。過去のassistant回答は固定データで、実際に21往復生成したものではない。同じ文章でもtokenizerによって入力token数が異なる。

|モデル・経路|入力token数|最初の表示まで|内容の保持|
|---|---:|---:|---|
|Qwen2.5 / WebLLM|2,533|85.46秒|保持。ただし中国語が混在|
|Qwen3 / WebLLM|2,537|198.21秒|保持|
|Qwen3.5 / WebLLM|2,044|155.45秒|保持|
|Qwen2.5 / wllama|2,533|95.33秒|保持|
|Qwen3 2507 / wllama|2,533|144.34秒|保持|

保持には成功したが、約2,000〜2,500入力tokenで1分半〜3分超の待ち時間になった。これもWindows参考値でありA16への速度換算はしていない。人による10分以上の会話、熱、背景遷移を含む実機試験は別に必要。[履歴試験原文](a16-evidence/supplement-context.json)

最後に5候補を1つずつ削除し、選択対象のエントリだけが消えること、他のWebLLMエントリ数とGGUF登録URLが保たれること、無関係なキャッシュが残ること、削除済みモデルのオフライン起動が明確に失敗することを確認した。全5件のassertionが通過。測定用モデルキャッシュは片付け、最後のorigin使用量estimateは約16.05MB（画面・runtime等）だった。estimateは非同期の概算で、各削除前後の差を正確なファイルサイズやディスク回収量とみなさない。[削除記録](a16-evidence/supplement-delete.json)

## 測定条件と留意点

固定質問は英語2問、方程式、御恩と奉公、光合成、漢字、画像不足、誤った前提、分数、未知の試験問題。質問と期待する観点は [questions.mjs](../experiments/a16/questions.mjs)。全モデルに同じ日本語system指示、文脈4096、出力上限256、temperature 0.2、top_p 0.9、seed 42を使用。WebLLMは各問でKVをリセット、wllamaは `cache_prompt:false`、CPU thread数1、GPU layer要求99。wllama 2候補はログで37/37層のGPU offloadを確認した。

WebLLMのQwen3系は非思考モード、2507版は元から非思考専用。別runtimeで同じseedでも同じ乱数列は保証されない。出力上限到達は順に0/2/2/0/5問で、2507版は長い説明が多く途中終了した。今回の評価を長い出力設定での能力上限とは扱わない。ただし誤読・年代・計算など、打ち切り前に生じた誤りは残る。

最初のQwen2.5 / WebLLM試行では思考モード指定を誤って適用したため、その回答はランキングから除外し、指定を取り除いて10問・会話・オフライン試験をすべて再実行した。`pilot-qwen25-misapplied-thinking.json` は経緯を検証できるよう保存してある。修正版の初回ロードは既にキャッシュがあり、他候補の初回取得時間と同じ条件ではない。

ブラウザのPage-target CDP通信カウントはWorker/Service Worker通信を網羅しないため、ダウンロード量やネット遮断の証拠に使わない。オフラインはサーバー停止・ページ再読み込み・未保存URLの取得失敗・Workerの外部取得禁止で確認する。`navigator.onLine` は切断条件でもtrueを返したため判定に使わない。

## A16への適用判断

物理iPad A16、Safariの実際の版、実RAM/GPU常駐量、熱による速度変化、背景復帰、画面ロック、OSが実際にメモリ不足でタブを終了した際の復帰は未確認。Workerの意図的終了から戻せても、OSによるOOMからの復帰を実証したことにはならない。

Apple/WebKitの仕様とruntime制約は [環境調査](a16-platform-research.md)。実機測定は [ラボの手順](../experiments/a16/README.md) に従い、本番とは別originのHTTPSで実施する。本番と同じGitHub Pagesホストの別パスは、撤去済みローカルAIのキャッシュ削除処理と干渉するため使わない。比較ラボ自体も本番ホストでモデルを起動しない。

Qwen2.5 **3B**のライセンスは `qwen-research`。他サイズのApache-2.0条件を流用しない。Qwen3/3.5、runtime、GGUF変換の出典と固定revision、runtimeのSRIはラボに保存。APIキー・有料推論・外部チャットサービスは使用していない。モデル重みとブラウザプロファイルはGitおよび配布ZIPに含めない。
